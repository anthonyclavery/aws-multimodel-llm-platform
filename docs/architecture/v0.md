# V0 Technical Architecture

## Purpose

V0 provides a small number of users with one interface for accessing and comparing multiple LLMs. It prioritizes operational simplicity, reproducibility through Infrastructure as Code, controlled costs and security appropriate for an Internet-facing service.

See the [V0 architecture diagram](../diagrams/v0-architecture.md).

## Components

| Area | Component | Responsibility |
| --- | --- | --- |
| Access | Public application hostname | DNS resolution to the public endpoint |
| Reverse proxy | Caddy | TLS termination, certificate renewal and proxying to LibreChat |
| Application | LibreChat | User interface and multi-model integration |
| Persistence | Authenticated local MongoDB | LibreChat users, conversations and application data |
| Compute | Ubuntu Amazon EC2 instance | Docker Compose host |
| Storage | Encrypted EBS `gp3` | Persistent volumes, including MongoDB data |
| AWS models | Amazon Bedrock | Model access through the EC2 IAM role |
| External models | Google Gemini API | Model access through a protected API key |
| Secrets | AWS Secrets Manager | Application and provider secrets |
| Administration | AWS Systems Manager Session Manager | Administration without public SSH |
| Observability | Amazon CloudWatch | Essential instance logs and metrics |
| Backup | EBS snapshots | Persistent-storage recovery |
| Documents | Amazon S3 | Document storage only when a concrete use case requires it |
| Lifecycle | AWS scheduling mechanism | Automatic nightly shutdown |
| Provisioning | Terraform | Network, security, EC2, IAM, storage and monitoring |

## Main Request Flow

1. An authorized user opens the public HTTPS endpoint.
2. Public DNS resolves the application hostname to the EC2 public endpoint.
3. The Security Group allows inbound HTTPS traffic on port 443 only.
4. Caddy terminates TLS and forwards the request to LibreChat over the internal Docker network.
5. LibreChat stores application data in MongoDB on the internal Docker network.
6. LibreChat accesses Amazon Bedrock through temporary permissions provided by the EC2 IAM role.
7. LibreChat accesses Google Gemini with a key retrieved from AWS Secrets Manager.

## Operations

The instance is started manually and automatically stopped every night to prevent accidental compute costs outside the intended usage window. EBS data persists while the instance is stopped, and the public endpoint remains stable.

V0 accepts service interruption while the instance is stopped and unavailability if the single EC2 instance fails. This trade-off is appropriate for a small-scale, non-critical workload.

## Infrastructure as Code

Terraform must cover at least:

- the VPC, public subnet, Internet route and Security Groups;
- the EC2 instance, Elastic IP and encrypted EBS volume;
- the least-privilege IAM role and Instance Profile;
- application secrets and narrowly scoped read permissions;
- the selected CloudWatch logs and metrics;
- the automatic nightly shutdown mechanism;
- EBS snapshots according to a retention policy to be defined.

External DNS configuration may remain documented or be automated separately with an appropriate Terraform provider.

## Out of Scope for V0

- Application Load Balancer and Multi-AZ architecture;
- private subnet with a NAT Gateway;
- ECS/Fargate and Kubernetes;
- API Gateway, Lambda and microservices;
- a custom-built LLM gateway;
- high availability and horizontal scaling;
- continuous operation for autonomous AI agents.

## Reassessment Criteria

The architecture must be reassessed if the platform requires 24/7 availability, autonomous agents, sustained concurrent usage, high availability, stricter security constraints, horizontal scaling or if its operating costs exceed those of an equivalent managed solution.
